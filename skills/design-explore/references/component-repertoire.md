# Component and effect repertoire

Use this when exploring possibilities for a website or app, or looking for a concrete interaction or visual technique. The names are retrieval cues: bring relevant possibilities into consideration, then choose, combine, adapt or invent according to the brief. A catalogue is neither a complete account of design nor a list of elements a page should contain.

## Expressive possibilities beyond the category names

The dedicated collections provide more specific search cues. These are examples of available treatments, not project preferences or a fixed style vocabulary.

- [ASCII art](https://21st.dev/community/ascii): character-based imagery, portraits, scenes and patterns.
- [Gradients](https://21st.dev/community/gradients): atmospheric fields and layered colour, directional ribbons and bands, dithered patterns, focal glows, rings and sweeps.
- [Shaders](https://21st.dev/community/shaders): flow fields, waves, smoke, silk, aurora, caustics, mesh drift, metaballs, plasma, warped stripes, halftone, paper texture, water, image dithering, noise, liquid metal, glass, light rays and Voronoi patterns.

Their design value depends on how they change perception, attention, atmosphere or interaction in this project. Consider expressive treatments alongside composition, typography and content, rather than decorating a finished generic layout by category. The agent owns these choices; this index is not a questionnaire for the user.

For material behaviour, spatial interaction, image smearing, chromatic fringing and rendering choices including WebGL and Three.js, read [expressive-interaction.md](expressive-interaction.md).

## Using reference catalogues

Use 21st.dev as an optional source of current examples, previews and implementation references. Browser access is enough for discovery; this reference does not require its skill, MCP or packages. Search when a concrete example would improve an idea or answer an implementation question. Extend the search beyond this provider when appropriate.

Borrow the useful mechanism and adapt it to the project's identity, content and existing stack. Decide whether to implement it directly, reuse a project component or retrieve suitable third-party code. Check the actual dependencies and licence when reusing code. A catalogue listing does not establish suitability, accessibility or performance for the current project. Verify those in the resulting work through the existing Design Layer workflow.
