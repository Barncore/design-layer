# Design Explore

Apply the shared [creative philosophy](../design-router/references/creative-philosophy.md). Choose the exploration mode that resolves the uncertainty. Keep comparisons focused and make a recommendation; the user need not specify every design parameter.

Read the current project brief (`DESIGN-BRIEF.md` or its established path) when present. For a website or app UI whose project intent has not yet been translated into a shared direction, use [intent-interview.md](../design-router/references/intent-interview.md). Continue from existing answers; a focused comparison within an established direction does not need another interview.

For the visual interpretation that opens round three of the intent interview, use [visual-understanding.md](../design-router/references/visual-understanding.md). Its purpose is to check the understanding behind a direction before treating a concept as a build target.

When broadening web or app ideas, consult [component-repertoire.md](references/component-repertoire.md) for component and effect families and optional reference catalogues. When experimental interaction, spatial or material behaviour, or expressive motion could define the experience, read [expressive-interaction.md](references/expressive-interaction.md) while developing the concept; the user need not name a technique first.

## Mode A: concept exploration

Use when the direction itself is unsettled. Develop a strong direction and add contrasting concepts when they help resolve a real choice or the user requests alternatives. Concepts should differ in underlying visual and interaction logic, not just color.

For each concept define:

- thesis and emotional register
- subject-grounded visual language
- hierarchy and spatial model
- typography and palette roles
- signature idea
- motion posture
- strongest upside, largest risk, and likely dealbreaker

Hold the product job, audience, content requirements, accessibility floor, and technical constraints invariant. Recommend one concept only when the evidence supports it; otherwise name the decision that remains.

## Mode B: controlled calibration

Use when one direction exists but one named axis needs tuning. Use as many variants as the comparison needs, on that axis only. State the invariants before presenting them.

Good axes include density, contrast, expressive intensity, spatial depth, information emphasis, motion energy, or copy register. Bad axes are vague bundles such as "make it nicer."

Label variants by meaningful position, for example `quiet / balanced / vivid`, not `A / B / C` alone. Keep all non-axis variables fixed as tightly as the medium allows.

Read [variant-protocol.md](references/variant-protocol.md). For motion axes, also read [motion-language.md](references/motion-language.md).

## Evaluation

Evaluate every option against the same compact rubric:

- product fit
- clarity and usability
- distinctiveness without costume
- taste fit, with evidence source named
- implementation cost and risk

Do not average away a hard failure. A concept that violates accessibility or the brief is not a daring option; it is just broken in a nicer hat.

## Output

Present the recommended direction and the reasoning that matters to the brief. When comparing options, name their differences and invariants. Build requested comparisons to equivalent fidelity so presentation quality does not predetermine the choice.
