# Show your understanding visually

Use this to open round three of the project intent interview, after digesting the answers from round two. It also applies whenever a visual interpretation would help establish a new creative direction outside that interview. Generate an image that expresses your interpretation of the brief so the user can catch mistaken assumptions, refine the intended experience and recognise promising ideas before detailed design or implementation.

Use the available `imagegen` skill and built-in image tool. Choose a representative composition, scene or screen that makes the important interpretations visible. Let the brief determine the visual approach. An image should communicate the project's particular character and priorities, with enough concrete context for the user to assess your understanding. Further images are useful when they expose meaningfully different interpretations or clarify a correction.

Frame the generation around the intent, audience, desired experience and provisional ideas you want to express. Preserve established product facts and constraints. Make creative inferences yourself, while keeping invented features and claims out of the project's apparent requirements. When an important interpretation concerns behaviour, describe it alongside the image or use a small working example if that would communicate it better.

Present the image as an interpretation to discuss. Explain the few consequential connections between the brief and your visual choices, including assumptions the image makes. Invite the user to correct what the project seems to promise, whom it seems to address or how the experience comes across. Concrete work should make those reactions easier than prescribing an unseen design.

Treat feedback at the level the user gives it. Agreement with the intended feeling or project interpretation leaves incidental layout, colours, typography and components open. This image is an expression of understanding, not a final website specification. Use the clarified intent to develop the design further; fidelity to the image becomes an implementation requirement only when the user explicitly chooses it for that purpose.

Update the evolving brief with the image location, interpretations confirmed or corrected, promising ideas and remaining choices. Mark superseded images so they cannot become accidental build targets. Review these distinctions before proceeding within the task's authorised scope. If the user explicitly delegates continued work without feedback, retain the interpretation as provisional rather than recording approval.

Carry forward an existing visual interpretation when it already does this job. Respect requests to skip images, keep work text-only or make a scoped change within an established direction. If image generation is unavailable, explain the limitation and use the closest useful representation allowed by the task.
