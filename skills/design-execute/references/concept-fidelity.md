# Carry a concept into the build

Use this when an approved reference, prototype, image or composition already establishes a direction. The job is to preserve what makes that direction work while making it usable.

Check the reference's role in the current brief. An image made through [visual-understanding.md](../../design-router/references/visual-understanding.md) expresses a provisional interpretation. Agreement with that interpretation does not make the pictured layout, assets or styling a literal build target. Carry forward the confirmed intent; apply image fidelity only to the design choices the user has actually selected.

Identify the few relationships that define the concept: the balance of masses, type-to-image ratio, focal point, empty space, density, material treatment and sequence of attention. Separate those from incidental screenshot details. A polished implementation can still fail if it replaces the defining composition with familiar components.

Work from real assets or honest placeholders with the same compositional role. A photograph, illustration, texture and live data display are different media; do not silently replace one with an easy gradient. Inspect cropping, subject scale and negative space together with the typography.

Translate the concept to actual content, semantic controls, keyboard use, text growth and smaller screens. Preserve the reading order and defining relationships rather than scaling down a desktop screenshot. Explain a material departure and its reason. Do not ask about routine adaptations that preserve the intent.

Compare the rendered result with the reference at the composition level before tuning pixels. Then inspect type metrics, optical alignment, spacing, asset quality and interaction states. State which parts were actually rendered. This reference governs implementation of a supplied concept; it does not initiate an image-generation workflow.
